# 草场轮牧载畜采证台

草场许可、牲畜群转场、植被样方和休牧恢复证据共同决定草场能否继续放牧及超载补偿；巡护设备可离线补传。

三套子系统通过原始证据、SQLite 状态与版本化决定互相影响。

```powershell
python -m pip install . --no-deps --no-build-isolation
python -m rangeledger init --db work.db
python -m rangeledger demo --db work.db
python -m unittest discover -s tests -v
```

命令：permit, movement, recovery。每个命令通过 `--fixture` 读取单一子系统的 JSON；`demo` 依次执行正常样例。每项报告列证据 ID 和决定版本。


## 配额、占用与恢复语义

许可期限与畜群实际入离场时间比较。转让事件按时间依次更新出让方和受让方余额；余额不足的转让判为超配。占用按草场、耳标畜群和牧户分组，重叠的同一畜群时段只取一次最大头数；防疫隔离阻止合法通行，但实际占用仍计入生态压力。夜间越界以每天 20:00–次日 06:00 的区间交集计算小时，补偿按牧户压力占比和越界时长分摊。

休牧令保持历史。撤销活跃休牧令后，必须收到晚于原命令的植被样方，且占用、草量与检疫条件都允许，才能重开。`python -m rangeledger replay --db work.db --subject case-1` 从原始证据重算十项决定，发现被篡改的最新报告时返回差异。

## 离线水管网：有向水量账与漏损归责

`fixtures/water-loop.json` 是固定合成管网，每条流水带唯一 `edge_id`、方向（`from`→`to`）和绑定仪表：总进水 100，首轮分 A 饮水 40、B 支路 50、蓄水池直入 5、主管漏 5；B 的 50 拆为 30 实喝与 20 内部回流，滤池把回流的 18 送入蓄水池、损耗 2。

- `water_meter.py`：`delta` 永远是 after-before；读数先 HMAC 验签再按表计分组、按时刻排序、同点去重、相邻差求和；校准因子按事件时刻生效，换表/归零事件后的首读数以新表 `prior_reading` 为前值。签名规范与 SQLite 入库 JSON 口径一致，证据经库存重放后验签仍然成立。
- `water_ledger.py`：在流图上逐节点闭合。外部进水 = 牛群实耗 + 蓄水增量 + 有证漏损 = 40+30+23+7 = 100；内部回流是边不是第二次新取水。每个节点给出守恒差额、关联仪表与冻结理由，差额超过 1 立方米容差（或缺表、验签失败、阀门异常）只冻结该节点及其下游牧户凭证，绝不摊给所有牧户。`naive_return_as_new_intake` 与 `naive_branch_fully_booked` 固定复现常规采集全对却记成 120 的两个反例；回流表 20→18+2 是滤池损耗的定位证据，不可删。
- 漏损归责：同一闭合物理账按经签认的协议出具两套凭证。基础设施维护协议下管理方承担 7 方漏损，A/B 只计 40/30；共同管护协议下 7 按真实饮用量 40:30 分摊（A 4、B 3），管理方只登记物理漏损。凭证按协议独立版本化存入 `voucher` 表，引用签认事件与原始读数，不只是报表标签。
- 迟到水表/阀门记录通过 `impacted_nodes` 限定影响域，只重算与该边相连的节点，无关节点的守恒差额不变。原始读数、改表、校准、水位与签认版本均保留在 `evidence` 表，`save_node_balances` 把节点守恒差额作为版本化决定留存并可从原始证据重放复现。
