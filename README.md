# 草场轮牧载畜采证台

草场许可、牲畜群转场、植被样方和休牧恢复证据共同决定草场能否继续放牧及超载补偿；巡护设备可离线补传。围栏报警回路则经最小一致故障集诊断转为隔离试验与维修工单。

三套子系统通过原始证据、SQLite 状态与版本化决定互相影响。围栏诊断使用同一证据与版次机制，证据类型为 `fence_topology`、`fence_alarm`、`fence_retest`。

```powershell
python -m pip install . --no-deps --no-build-isolation
python -m rangeledger init --db work.db
python -m rangeledger demo --db work.db
python -m unittest discover -s tests -v
```

命令：permit, movement, recovery。每个命令通过 `--fixture` 读取单一子系统的 JSON；`demo` 依次执行正常样例。每项报告列证据 ID 和决定版本。


## 配额、占用与恢复语义

许可期限与畜群实际入离场时间比较。转让事件按时间依次更新出让方和受让方余额；余额不足的转让判为超配。占用按草场、耳标畜群和牧户分组，重叠的同一畜群时段只取一次最大头数；防疫隔离阻止合法通行，但实际占用仍计入生态压力。夜间越界以每天 20:00–次日 06:00 的区间交集计算小时，补偿按牧户压力占比和越界时长分摊。

休牧令保持历史。撤销活跃休牧令后，必须收到晚于原命令的植被样方，且占用、草量与检疫条件都允许，才能重开。`python -m rangeledger replay --db work.db --subject case-1` 从原始证据重算十项决定，发现被篡改的最新报告时返回差异。

## 围栏报警诊断、隔离复测与工单

每条报警表示回路至少一段断线，传感器自检全部通过时报警才被采纳。诊断枚举全部**最小一致故障集**（最小击中集）而非挑选单一故障：仅 AB、BC 报警时为 `{B}` 与 `{A,C}`；再加 AC 报警时为 `{A,B}`、`{A,C}`、`{B,C}`。交集为空、并集非最小、按频次单选或逐回路各选一段都无法在三报警下给出可证实结论，互斥候选必须并列保留。报警解释边把每条回路展开为“回路→区段”的约束边。

两条授权规程读取同一份输入：

* **夜间安全规程**不依赖复测，对候选并集内全部区段（A/B/C）下预防检查工单，原始候选原样保留；
* **定位规程**只接受 HMAC-SHA256 已签名的隔离复测（`fence_retest`）。C 从 AC、BC 切离后剩余支路仍报警，即证实 A、B 均断线，候选收敛为 `{A,B}` 并仅下 A/B 定位维修工单；复测缺签名或签名不符一律禁止定位。

拓扑以证据版次保存，旧版勘误后重算诊断自动升版，重复摄入与重复重算幂等。样例见 `fixtures/fence-loops.json`，验收测试为 `tests/test_fence_diagnosis.py`，运行 `python -m pytest -q`。
